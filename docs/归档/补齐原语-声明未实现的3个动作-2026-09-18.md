# 补齐它声明却没实现的动作（2026-09-18）

> 用户："**它原语中有了什么样的动作了？它原语能识别的动作我们都用我们的实现给它加上了吗？
> 我不想开发 mcp 了。**"
>
> **答**：**没有加全 —— 漏了 3 个，现在补上了。** 而且不用 MCP 完全可行，
> 因为**这 3 个【本来就在它的 enum 里】**。

---

## 一、它声明的「原语」vs `main()` 里【实际实现的】

**它声明**（`mobile_use/utils.py:303-316`）：
```
动作 enum（11 个）：
  key · click · long_press · swipe · type · system_button · open · wait · answer · interact · terminate
system_button 的子动作 enum（4 个）：Back · Home · Menu · Enter
→ 合计 15 个"原语"
```

**改动前 `main()` 实际有分支的**（`run_gui_owl_1_5_for_mobile.py:225-296`）：
```
实现：click · long_press · swipe · type · system_button · open · wait · answer · interact · terminate
      + 子动作 Back · Home
→ 合计 12 个
```

**★ 漏 3 个**（落到 `else: print("[WARN] Unsupported action type")` **被静默丢弃**）：

| 漏项 | schema 里的说明 | 后果 |
|---|---|---|
| **`key`** | "Perform a key event. supports adb's keyevent syntax. Examples: volume_up / volume_down / power / camera / clear" | **音量、电源、清空输入 —— 全都发不出去** |
| **`system_button{Menu}`** | "Menu means opening the application background menu" | 打不开 App 切换器 |
| **`system_button{Enter}`** | "Enter means pressing the enter" | **搜索/发送/确认按不了** |

## 二、★ 补齐方案：**这 3 个都能用我们的设备实现**（无需扩展 enum）

| 漏项 | 我们的实现 | 设备端现状 |
|---|---|---|
| **`key`** | 按名映射：`volume_up`→`volup` · `volume_down`→`voldn` · `power`→`power` · `mute`→`mute` · `clear`→`type.delete(count=200)` · `back`/`home`/`menu`/`enter`→方法 | **能力均已注册** ✓（`camera` 如实不支持）|
| **`system_button{Menu}`** | **`home.double`（双击 Home = App Switcher）** | **已注册** ✓ 且**语义完全对应**（比 Android 的 `keyevent MENU` 更贴）|
| **`system_button{Enter}`** | **过渡**：粘贴换行；**正解**：设备端 HID 支持 `@"RETURN"`（`STHIDEventGenerator.mm:1425`）但**注册表未暴露** | ⚠️ **需设备端补 `keyboard.key` 能力** |

**★ 关键**：**这 3 个都在它【已声明的 enum 里】**
→ **补它们不需要改动作空间、也不需要改提示词** ✓
→ **属于「修它声明了却没实现的洞」，PR 完全可以理直气壮** ✓✓✓

## 五、★ 顺带修正：能力盘点漏了 9 个（64 而非 55）

**原因**：设备端能力有**两种注册方式**，我上次只 grep 了第一种 ✗

```objc
①  _registerControl:@"x"  ...                字面量      55 个
②  NSArray *hidNoParam = @[ @{@"id":@"x",...} ]  数组+循环  9 个  ← ★ 上次漏了
```

**漏掉的 9 个**（`TRCapabilityRegistry.mm:266-276`）：
```
spotlight（下拉搜索）· home.double（双击Home）· home.long（长按Home）
power.double（双击电源）· power.triple（三击电源）· power.long（长按电源）
hwlock（硬件键盘锁）· hwunlock（硬件键盘解锁）· releasekeys（释放所有按键）
```

**→ 设备端能力总数 = 64 个**（不是 55）

**★ 其中 `home.double` 正好成了 `system_button{Menu}` 的实现** ✓✓✓

## 六、结论：**不用 MCP，在它原语框架内就够**

| 上一版的判断 | 修正 |
|---|---|
| "要做 MCP，它是唯一能扩交互动作的路" | **不完全对** —— **它 enum 里【已经声明】的动作还没实现完** ✓ 先把这些补上 |
| "MCP 是必选项" | **改判**：**MCP 是"扩展 enum 之外的动作"才需要**；<br>**当前 enum 内的补齐（3 个）不需要 MCP** ✓ |

**★ 但有一个边界要说清** ✓：

| 能力 | 当前 enum 里有位置吗 |
|---|---|
| `key` · `Menu` · `Enter` | **有** ✓ 已补 |
| `home.double` | **有**（作为 `Menu` 的实现）✓ |
| **`spotlight`（下拉搜索）** | ✗ **没有** —— 除非走 `key("spotlight")` 或扩 enum |
| **`power.double` / `power.triple` / `power.long`** | ✗ **没有**（`power` 只有单击）|
| **`hwlock` / `hwunlock` / `releasekeys`** | ✗ 没有 |
| **`pinch` / `taps` / `curveSwipe`** | ✗ 没有 |
| **`clipboard.get`** | ✗ 没有 |
| **`type.delete` 单独动作** | ✗ 没有（只能走 `key("clear")` 或 `key("backspace")`）|

**→ 所以**：**当前 enum 内的洞补完了 ✓；再多的能力（spotlight / 双击电源 / 手势 / 剪贴板…）在它的 enum 里没有入口** ✗
**→ 那一部分才需要 MCP（或扩 enum，但扩 enum = 改它的动作空间 ✗）**
