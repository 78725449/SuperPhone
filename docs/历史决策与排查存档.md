## bootstrap job 才读 pbxproj —— 阶段 3 五连败根因链（2026-08-25）

- **bootstrap job 才读 pbxproj（2026-08-25，阶段 3 五连败根因链）**：default/rootless/roothide 出 .deb（theos gmake 直接编译源码，**不读 xcodeproj**），仅 bootstrap 用 `xcodebuild -scheme TrollVNC` 构建 App——**App target（pbxproj）改动只在 bootstrap job 暴露错误，其余 3 scheme 全过也可能失败**。排查特征：default/rootless/roothide success 而 bootstrap 的 `Build package (bootstrap)` failure。bootstrap 相关坑（按出现顺序）：
  1. **pbxproj 对象 ID 同表必须唯一**（FileRef 段重复 ID → xcodebuild `Unable to read project ... damaged due to a parse error`）；`git show` 看存储版（LF）且建议本地跑一个 OpenStep tokenizer 校验（括号配平/每行分号/ID 冲突），Windows 无 xcodebuild 无法本地解析 pbxproj。
  2. **pbxproj 含 `+` 的 path 必须加引号**：Xcode 旧式 plist 解析器不接受裸字符串中的 `+`（category 文件名如 `BRDatePickerView+BR.m`）→ 报 `missing semicolon in dictionary`。含特殊字符的 path 一律 `path = "...";`。
  3. **workflow 的 xcodebuild 命令行覆盖 HEADER_SEARCH_PATHS**（bootstrap.sh 传 `HEADER_SEARCH_PATHS=$(SRCROOT)/../../include`）→ **pbxproj 里的 HEADER_SEARCH_PATHS 对 bootstrap 无效**；引号 import 外部头（如 BRPickerView）必须用**相对路径** `#import "BRPickerView/BRTextPickerView.h"`，勿依赖 HEADER_SEARCH_PATHS。
  4. **.mm 里 C 函数被 .m 调用必须 `extern "C"`**：ObjC++（.mm）全局函数默认 C++ linkage（mangled），ObjC（.m）侧按 `_kRegions` 引用 → 链接 `Undefined symbols`。TRRegions.mm/h 的 `kRegions` 即此坑（被 TRFillDataViewController.m 调用）；若被调用方全是 .mm 则两边 mangled 一致无需处理（TRCorpus 等）。
  5. 构建产物 .mm 的 ObjC 字典 key 必须 `@` 前缀（`@{@"text": ...}`，生成脚本易漏）。
