# WiFi 定位伪装 POC · 设计稿

> **目标：** 验证"双层注入"能否让风控可见的 WiFi 指纹与 GPS 模拟坐标完全自洽——
> A 层（locationd 服务层，`CLSimulationManager`）喂目标城市 BSSID 扫描结果；
> B 层（目标 App 进程内，netdisguise/fishhook）拦截 SDK 对 wifi 扫描 API 的调用。
> **核心洞察：** 风控 SDK 嵌在目标 App 进程内，看世界的唯一方式是"进程内发 API 调用"——它
> 不可能绕过 API 读 airportd 内存。因此 B 层进程内拦截 + A 层 locationd 服务的双层叠加，
> 即"风控体感上的全系统扫描源覆盖"。
> **状态：** 设计稿（未实现）。A 层字典键名无公开资料，采用"初始猜想 + XPC 载荷取证校准"双轨。

---

## 1. 背景与论证结论（前情摘要）

### 1.1 时序事实（已确认）

- App 拿坐标的唯一通道：`CLLocationManager` → locationd XPC。WiFi 扫描、wloc 服务器查询、解算、融合**全部由 locationd 代劳**（证据：acheong08 apple-corelocation-experiments 流量分析 + locationd 日志 `WifiScan, addAp, ..., rssi, -28, channel, 13, age, 2.5, timestamp`）。
- WiFi 扫描源真实分层：内核 `IO80211FamilyV2` → `airportd`（root daemon，扫描 owner）→ locationd/WiFiManager 等消费方 → App 进程（经 Apple80211/CoreWiFi 私有框架或 CLLocationManager 私有扫描方法）。

### 1.2 TrollStore 能力边界（已确认）

| 能力 | 结论 |
|---|---|
| 任意 entitlements / 任意签名 | ✅ |
| 以 root 运行**自己的**二进制 | ✅（`com.apple.private.persona-mgmt` / `/cores/root_wrapper`，injectctl 已用） |
| 向系统进程（airportd/locationd）注入代码 | ❌（需 TF_PLATFORM + PAC bypass + PMAP bypass，越狱级） |
| 生成 Launch Daemon / 全平台化 | ❌ |

**推论：** 物理层（airportd/内核）改不了也不需要改——没有任何 SDK 能绕过 API 读 airportd 内存；
风控可观察层（目标 App 进程 + locationd 服务）**完全能覆盖**。

### 1.3 双层注入模型

```
坐标层（已有）：  manager daemon → CLSimulationManager.appendSimulatedLocation: → locationd 广播目标坐标
指纹层（本 POC）：A 层 manager → setWifiScanResults:[目标城市 BSSID] + startWifiSimulation   （locationd 服务层）
                 B 层 目标 App 进程内 fishhook/swizzle 拦截 wifi 扫描 API 返回            （进程内兜底）
```

两模拟**不互斥**：GPS 模拟喂"结果"，wifi 模拟喂"输入"，作用层不同，叠加即自洽。

## 2. 技术方案总览

```
PC 端（已通）：scripts/apple-wps.mjs
    tile/query/expand → wps-expand-hz.json（801 个真实 BSSID+坐标，自洽验证通过）
                        │ 转 ObjC 常量（仿 build-tr-corpus.mjs 生成模式）
                        ▼
设备端：
  App（伪装页/定位 UI）── 选择伪装城市 → 从内置 WPS 数据取 BSSID 集
                        │ 写 mobile plist（wifi 伪装配置，含 BSSID[]）
                        ▼
  manager daemon（有 com.apple.locationd.simulation entitlement）
    读 plist → A 层：[sim setWifiScanResults:dicts]; setSimulatedWifiPower:YES; startWifiSimulation
    叠加 GPS 模拟（并发不互斥）
                        ▼
  目标 App（netdisguise 注入）：B 层——拦截 SDK 的 wifi 扫描 API 返回目标城市 BSSID
                        ▼
  三档观测：A=进程内自读扫描结果 / B=定位结果 source+坐标 / C=系统日志 WifiScan addAp
```

**技术栈：** ObjC（SimLocationManager）、C（netdisguise/fishhook）、Node（已是 WPS 数据源）、theos/CI（构建）。

## 3. A 层：CLSimulationManager WiFi 注入（locationd 服务层）

### 3.1 接口补齐

`TrollVNC/src/SimLocationManager.mm:19-37` 的 `CLSimulationManager` 私有接口段**补一条**（wang daemon dump 签名）：

```objc
- (void)setWifiScanResults:(id)scanResults;
```

### 3.2 新增注入方法（插在 `injectPoint:` 之后，`SimLocationManager.mm:96` 后）

```objc
// A 层 wifi 模拟入口：与 injectPoint: 叠加不互斥（GPS 喂结果、wifi 喂输入）。
// scanResults：NSArray<NSDictionary>，键名见 §3.3（初始猜想，取证校准）。
- (void)injectWifiScanResults:(NSArray<NSDictionary *> *)scanResults {
    if (!_sim || scanResults.count == 0) return;
    [_sim setWifiScanResults:scanResults];
    [_sim setSimulatedWifiPower:YES];
    [_sim startWifiSimulation];
    _wifiSimulating = YES;
}

- (void)stopWifiScanSimulation {
    [_sim stopWifiSimulation];
    [_sim setSimulatedWifiPower:NO];
    _wifiSimulating = NO;
}
```

（`_wifiSimulating` 需在 41-44 行 ivar 区补 `BOOL _wifiSimulating;`）

### 3.3 字典结构：初始猜想 + 取证校准

**键名无公开资料**（5 轮检索零调用示例）。初始猜想依据 locationd 日志字段
（`rssi/-28, channel/13, age/2.5, timestamp`）+ CoreLocation XPC plist 约束：

```objc
NSDictionary *ap = @{
    @"bssid"     : @"a4:83:e7:3f:2c:91",  // 目标城市 WPS 真实 AP（Apple 数据库确认存在）
    @"ssid"      : @"CMCC-4B2A",
    @"rssi"      : @(-55),                 // 随机 -40 ~ -90
    @"channel"   : @(6),
    @"age"       : @(0.5),                 // locationd 日志字段
    @"timestamp" : @([[NSDate date] timeIntervalSince1970]),
};
```

**取证校准（无越狱可执行关键一招）：** fishhook 在目标 App 进程内 hook
`xpc_connection_send_message`，抓 `CLSimulationManager → locationd` 的实际 XPC 载荷，
反推真实键名（见 §6 取证清单第 1 项）。校准后替换以下候选对照表：

| 猜想键 | 候选派生 | 证据 |
|---|---|---|
| bssid | bssid / mac / BSSID / MACAddress | locationd 日志 addAp |
| rssi | rssi / signalStrength / Rssi | locationd 日志 rssi |
| channel | channel / Channel | locationd 日志 channel |
| age | age / ageOfScan | locationd 日志 age |
| timestamp | timestamp / scanTimestamp | locationd 日志 timestamp |

### 3.4 数据源接入

- PC 端产物：`scripts/apple-wps.mjs expand --out wifi-hz.json`（801 AP，含 bssid/lat/lon）。
- 转内置常量：仿 `build-tr-corpus.mjs` 生成 `TRWifiSpoofData.m/h`（NSString 常量数组），编入 App target。
- 配置通道：App 伪装页/定位 UI 选择伪装城市 → 写 mobile plist（`TRWifiSpoofEnabled` + `TRWifiSpoofBssids`），manager 按既有 `prefs-changed` 机制读取（复用 `reloadFromPrefs` 指纹模式，把 wifi 配置纳入 `_paramsSignature`）。

## 4. B 层：netdisguise 进程内 wifi 扫描拦截（兜底）

### 4.1 拦截点清单（按 SDK 可能走的通道）

| 通道 | 形态 | 拦截手段 |
|---|---|---|
| CoreLocation 私有扫描（`startWifiScanning` 系，最可能） | ObjC 方法 | swizzle（netdisguise 已有 NWPath swizzle 样板） |
| Apple80211/CoreWiFi 私有框架（dlopen+dlsym 动态链） | C 函数 | **hook `dlsym`**，对 `Apple80211Scan` 等符号返回 wrapper |
| NEHotspotHelper / Network.framework | ObjC | swizzle（已有 NWPath 基线） |

### 4.2 netdisguise.c 改动（`nd_init` 构造区内追加注册）

```c
// ---------- 5. wifi 扫描拦截：dlsym 符号重定向（Apple80211 通道） ----------
static void *(*nd_orig_dlsym)(void *handle, const char *symbol);
static void *nd_dlsym(void *handle, const char *symbol) {
    void *p = nd_orig_dlsym(handle, symbol);
    if (p && symbol &&
        (strcmp(symbol, "Apple80211Scan") == 0 ||
         strcmp(symbol, "Apple80211ScanRequest") == 0 ||
         strcmp(symbol, "Apple80211GetInfo") == 0 ||
         strcmp(symbol, "Apple80211CopyInformation") == 0)) {
        return (void *)nd_wifi_scan_wrapper;   // wrapper 见下
    }
    return p;
}

// 假扫描结果生成：从注入方放入的数据区读目标城市 BSSID 集，按被测 API 形态填结构。
// POC 阶段先实现 Apple80211CopyInformation 形态（NSDictionary 返回，SDK 常见消费），
// 具体结构与真机 diag 对齐后校准。
static void *nd_wifi_scan_wrapper(void) { ... }
```

swizzle 骨架（对齐现有 `nd_usesInterfaceType` 写法）：

```c
// CLLocationManager 私有扫描 swizzle（启动扫描无参；结果经私有 delegate 回调，
// POC 拦截点：swizzle "setScanningEnabled:" / "_startWifiScanning" 返回 NO 或注入数据源）
static BOOL (*nd_orig_startWifiScan)(id, SEL);
static BOOL nd_startWifiScan(id self, SEL _cmd) {
    // 注入自备的数据源替代真实扫描；返回 YES 让 SDK 走"已扫描"回调路径
    return YES;
}
```

工具链联动：`injectctl diag` 扩展一条 `wifiscan` 子命令，注入前/后各读一次扫描结果，供观测 A 对照。

## 5. 三档观测点（POC 验收标准）

| 档 | 观测对象 | 方法 | 通过标准 |
|---|---|---|---|
| A | 进程内扫描结果 | `injectctl diag wifiscan`（注入目标 App 前后各一次） | 注入后 SDK 可见 BSSID 全为目标城市集合 |
| B | 定位结果 | 关 GPS 模拟，仅开 wifi 模拟；App `didUpdateLocations:` 记录 source+坐标 | `CLLocation.source == wifi 且坐标 ≈ 目标城市`（收敛 <2km） |
| C | 系统侧扫描日志 | 真机 sysdiagnose（wifi-buf 日志）/ `log stream` 抓 locationd `WifiScan, addAp` | addAp 的 AP 集合含目标城市 BSSID |

三档全部通过 → A 层键名猜想正确、B 层拦截生效、双层自洽成立。

## 6. 真机取证清单（无越狱路径）

1. **XPC 载荷取证（最高优先，定 A 层键名）**：新增 `netdisguise` 或独立 diag 工具 fishhook
   `xpc_connection_send_message`，打印 `setWifiScanResults:` 执行瞬间送往 locationd 的 dict 键列表，
   与 §3.3 候选对照表比对 → 确定真实键名。
2. **SDK 通道确认**：在目标 App 内 hook `dlopen`/`dlsym`+`objc_getClass`，记录 SDK 实际请求了哪些
   wifi 相关符号/类（`CLLocationManager` 扫描方法 or `Apple80211*`）→ 决定 B 层按哪个形态实现。
3. **系统日志对照**：sysdiagnose 提取 `wifi-buf-*.log`，核对注入前后系统侧扫描是否仍为真实 AP
   （若系统侧仍真实——属预期：airportd 物理层不可改；观测 C 只看 locationd 消费面）。
4. **环境记录**：注入前记录真机周边 BSSID 全集（对照组），注入后重扫对比。
